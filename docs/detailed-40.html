40-question fire-only assistant benchmark

Measure the behavior you actually need

Use the book first. Answer missing fire-safety questions from reliable general knowledge. Refuse unrelated questions. This rerun tests that policy with 40 prewritten cases and six retained model configurations, twice: 480 recorded responses.

Task success, factual correctness, refusal, and source attribution are separate measures. A correct out-of-book fire answer is successful; a factually correct answer to an unrelated question still violates the domain rule. Repetitions are not independent quality samples.

Source handling and citation formatting

Citation labels on book answers are format compliance, not verified entailment. Fallback source handling requires acknowledging general knowledge or absent material without pretending the missing definition is in a book paragraph. A correctly labeled response can still be wrong or contain no answer. Source acknowledgment can pass for a refusal that accurately says the context lacks the information; read it alongside knowledge correctness.

Extraction, retrieval, and absence checks
The original PDF is preserved. Poppler text extraction retains PDF page numbers. A documented set of spacing repairs on page 4 restores visibly correct words such as “Test each alarm”; no facts or model outputs are changed. Page-local overlapping chunks are embedded with the same 23 MB MiniLM ONNX encoder as the NASA test. SQLite stores normalized 384-dimensional vectors and FTS5 text; NumPy cosine and FTS5 BM25 are fused by reciprocal rank with k=60. All models receive the same frozen top-five lists, not hand-selected paragraphs. The 8 fallback definitions were checked against the full book and separate official references. Two clearly labeled synthetic stress cases replace only passage 5; their natural retrieval lists are preserved and they are not attributed to the PDF.

Reproduce the policy and interpret the results
All 40 questions and expected behaviors were saved before inference. Six configurations ran twice, one model at a time. The suite is purposive, not random, blind, or a general model leaderboard. Some related fire concepts are correlated, so neither 40 cases nor repeated runs justify population confidence intervals.


Controls and limitations


The current system prompt


The policy is in the request, not enforced by the raw inference server. Unity must send this system message with every request. The ready-to-use client is ask_fire_context.py; example_fire_rag_request.json contains the payload. The old ask_context.py remains strict-context for reproducing the earlier NASA and 16-question runs.


How scoring works
Task success checks the expected answer or behavior. Factual status separately distinguishes correct, incorrect/incomplete, unanswered, and material unverified detail on 28 answerable fire questions. Domain refusal is checked on eight unrelated requests. Fallback source handling is checked separately from whether the fallback facts are correct. No external model graded the responses; saved answer hashes bind manual judgments to exact texts.


Strict-context results are archived under history/strict-context-amended-16/, and the original metals-question suite is also retained. They use a different policy and smaller question set, so their scores and timings are not pooled with this rerun.


Not measured
  • Quest 3 / 3S inference, peak model RAM, Unity frame rate, power, or thermals.
  • Broad reliability, comprehensive adversarial robustness, all jurisdictions, or production safety.
  • Cold startup, streaming first-token time, randomized model order, or exhaustive prompt tuning.
