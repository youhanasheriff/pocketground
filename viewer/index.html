Why are eight questions separate?

These ask about fire safety but require facts absent from the booklet. They test the model’s knowledge fallback, rather than its use of retrieved evidence. Their answers and failures remain visible under “Beyond the book.” The split was chosen after the original 40-question run; no prompt, answer, or judgment was changed.

Good document answers do not guarantee good boundaries.

Keep these capabilities separate. A model can extract the right answer and still accept unrelated requests or mishandle conflicting context.

One question. The same five passages. Every model.

  1. Freeze the evidence. Retrieve five passages once for each question. Every model receives identical system and user messages.
  2. Generate an answer. Use the pinned model and its native template, with reasoning and tools disabled.
  3. Review the response. Compare it against the expected behavior and source text. Preserve the exact answer and a reason for each failure.
  4. Show the separate results. Document answers, domain boundaries, uncertainty/stress, source formatting, size, and speed.

What this release measures

PocketGround 0.1.0 is an exploratory fixed-context RAG generation benchmark. It isolates how a model uses supplied retrieval results. It does not rank retrievers or test every part of a deployed RAG application.

How grading works
Task success follows each question’s expected behavior. Document questions require the requested facts without material unreliable extra advice. Domain questions require refusing unrelated requests. Handling questions require the specified unknown, clarification, conflict disclosure, or injection resistance. These are different tasks; a combined core total is a convenience, not universal accuracy.
Factual labels are correct, incorrect/incomplete, unanswered, or unverified extra detail. Scope and handling use task success instead of a factual label. Knowledge-source disclosure is separate. Paragraph citation presence is detected mechanically; full claim-level citation entailment has not been audited.
Each distinct answer was reviewed manually; repeated judgments were reused only after exact text equality was verified. An independent expert review and inter-rater agreement study have not been performed. Twelve responses reached the 192-token cap and remain in the record.


Limits and what should come next
The 40 questions are purposive and related, drawn around one U.S. home-safety booklet. They are not a random sample, a held-out multi-domain test, or a production certification. The 32/8 reporting split was selected after collection. Its policy still permits reliable general knowledge for in-domain gaps.
Future releases should add fresh held-out documents and domains, larger boundary and injection sets, independent scoring, and real-device measurements. A change to the prompt, template, model, retrieval, or grading policy defines a different configuration; preserve and identify it separately.


Related work
SLM RAG Arena focuses on sub-5B models and blind pairwise preference. MiniRAG / LiHua-World addresses lightweight on-device RAG and evidence-backed tasks. SLM-RAG-EVAL provides a compact-model generation study and a public reproduction package.
PocketGround emphasizes sub-1 GB model files, exact frozen inputs, separate behavioral checks, and visible grading evidence. This is a scope description, not a claim to be the first benchmark with these features. Other projects’ scores are not directly comparable.


Reproduce it without installing a Python package.
python3 pocketground.py verify
python3 pocketground.py inspect
python3 pocketground.py run --model quest-chat --label my-model --out runs/my-model.json
python3 pocketground.py review-sheet runs/my-model.json --out runs/my-model.review.json
# Complete the manual judgments, then:
python3 pocketground.py score runs/my-model.json runs/my-model.review.json
Requires Python 3.10+ and a separately configured local chat-completions server for inference. Start with README.md and docs/REPRODUCE.md in the package. The report itself works offline.
